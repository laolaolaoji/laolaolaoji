# LTX Astro 编辑式个人主页设计规格

日期：2026-07-23

## 目标

把现有无构建系统的单页主页改造成基于 Astro 的现代静态网站。首版仍是一张单屏数字名片，重点呈现 LTX 的个人品牌、开发者身份与视觉品位，不扩展项目列表、履历或博客。

成功标准：

- 访客能立即识别 LTX 是全栈开发者、Linux 爱好者、Web 设计者与创作者。
- 页面有明确的“独立技术杂志封面”记忆点，同时保持内容克制。
- GitHub 与 Reddit 两个现有社交入口可用。
- 页面底部完整、清晰地保留“鄂ICP备17028589号-4”，并链接到 `https://beian.miit.gov.cn/`。
- 同一份纯静态构建产物可部署到 GitHub Pages 和现有 nginx 服务器。

## 范围

### 包含

- Astro 静态站点工程与生产构建配置。
- 单屏响应式个人主页。
- LTX 身份介绍、GitHub、Reddit、备案信息。
- 基础 SEO、Open Graph 元数据、favicon、`robots.txt` 与 `ads.txt`。
- 可访问性与减少动态效果支持。
- 调整现有 `build.sh`，部署 Astro 的 `dist/` 产物。

### 不包含

- 项目作品集、履历、技术栈清单或博客。
- CMS、数据库、服务端接口或用户账户。
- 新增未经确认的邮箱或社交平台。
- 依赖客户端框架才能呈现的交互。

## 技术方案

采用 Astro 作为静态站点生成器，构建输出为纯静态 `dist/` 目录。页面默认不加载客户端框架运行时；仅在确有必要时使用少量原生浏览器脚本，核心信息在 JavaScript 禁用时仍完整可见。

选择 Astro 的理由：

- 默认静态输出和低客户端开销适合单页主页。
- 组件边界清晰，便于维护精细页面结构。
- 资源和字体处理适合视觉完成度较高的页面。
- 将来增加 Markdown 内容时无需再次迁移工具链，但本次不预建博客能力。

`npm run build` 生成 `dist/`。GitHub Pages 发布该目录；`build.sh` 在本地完成生产构建后，只压缩并上传 `dist/` 中的文件，保留当前 SSH、SCP、远程目录与 nginx reload 流程。

## 信息架构与组件

页面由以下单一职责单元组成：

- `Layout`：HTML 外壳、全局样式、SEO 与 Open Graph 元数据。
- `Hero`：刊头、在线状态、主标题和身份文案。
- `SocialLinks`：GitHub 与 Reddit 的编辑式文字链接。
- `OrbitArtwork`：纯 CSS 抽象轨道图形，不承担信息传达。
- `Footer`：备案信息及工信部链接。

站点文案和外部链接集中在一个类型明确的 Astro/TypeScript 数据模块中，组件通过属性接收内容。组件不得重复硬编码社交地址。备案文本可以由配置提供，但 `Footer` 必须始终渲染该文本，构建验收必须直接检查最终 HTML。

## 视觉设计

视觉方向为“A · 编辑部极简”，整体像一张独立技术杂志的封面：

- 暖纸色作为主背景，墨黑文字作为主要对比色，使用一个克制的强调色。
- 标题使用有性格的开源衬线字体，正文与功能文字使用清晰的开源无衬线字体；字体不可用时使用稳定的系统回退字体栈。
- 左上角使用小型刊头 `LTX / DEV` 与简洁在线状态。
- 主视觉在中央偏左，以超大标题 `Hello, I’m LTX.` 建立层级，保留现有身份含义。
- GitHub 与 Reddit 以带编号的文字链接呈现，而非大型平台图标。
- 右侧使用 CSS 绘制的抽象轨道，表达系统、网络与创造，不引入装饰图片依赖。
- 背景包含低对比度网格标尺和细微纸张质感；装饰不得影响文字可读性。
- 页脚作为独立页面区域，备案信息不能与社交链接混排、遮挡或置于装饰层下方。

桌面端采用不对称双区域构图。窄屏切换为自然纵向文档流，轨道图形缩小并退居背景；页面不得出现横向滚动。备案页脚位于内容流末尾，在内容较少时仍靠近视口底部，在小屏或内容增高时随文档自然下移。

## 动效与交互

- 首次载入时，刊头、标题、简介和社交链接按阅读顺序进行短暂分层揭示。
- 社交链接悬停或键盘聚焦时出现细线滑动和箭头轻微位移。
- 抽象轨道仅允许低频、低幅度的环境运动。
- `prefers-reduced-motion: reduce` 下关闭装饰运动与位移动画，内容直接显示。
- 所有外部链接可通过键盘访问并具有清晰的 `:focus-visible` 状态；新窗口链接使用安全的 `rel` 属性。

## 内容与容错

页面核心内容不依赖远程 API、CMS 或客户端数据请求。外部字体加载失败时采用回退字体，外部链接不可达时不影响其余页面。CSS 装饰失效时仍保留符合语义的标题、简介、链接和备案页脚。

保留现有 favicon、`robots.txt` 与 `ads.txt`。Google AdSense 脚本不作为首屏核心依赖；若继续保留，应异步加载，失败时不能造成布局空洞或控制台阻断错误。

## SEO 与语义

- 设置准确的页面标题和中英文可读描述。
- 提供规范链接及基础 Open Graph 标题、描述和类型。
- 使用一个 `<h1>`，社交入口使用语义化列表，备案信息位于 `<footer>`。
- 装饰图形从辅助技术中隐藏。
- 页面语言属性与主要文案语言一致；品牌名和职业短语可保留英文。

## 验收与验证

实现完成后必须验证：

1. 依赖安装和生产构建成功，`dist/index.html` 存在。
2. 最终 HTML 包含精确文本“鄂ICP备17028589号-4”和链接 `https://beian.miit.gov.cn/`。
3. 最终页面包含正确的 GitHub 地址 `https://github.com/laolaolaoji` 和 Reddit 地址 `https://www.reddit.com/user/fasting_sleep`。
4. JavaScript 禁用时，身份信息、社交链接和备案信息仍可阅读与使用。
5. 常见桌面与移动视口不存在横向溢出，页脚不会覆盖正文。
6. 键盘可以访问所有链接，焦点样式清晰。
7. 减少动态效果设置生效。
8. `build.sh` 打包的是最新 `dist/` 产物，而不是旧版源文件。
9. GitHub Pages 与 nginx 均可使用同一份构建产物，不依赖服务端路由重写。

## 实施约束

- 不虚构新的个人信息或社交链接。
- 不增加与单屏数字名片无关的功能。
- 备案信息属于不可回归项；任何页面结构调整都必须保留它。
- 视觉装饰不得以牺牲性能、语义或移动端可用性为代价。
